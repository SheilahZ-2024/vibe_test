# Demo 样本对照与演示指南

120 个 mock 用户，每人 **1 订单 + 1 团购券**。`user_XXX` 与 `order_XXX` / `voucher_XXX` 后三位编号一致。

前端顶部 **Demo 用户切换器** 可直接选择用户。

---

## 一、总览

| 类型 | 用户编号 | 订单编号 | 数量 | 说明 |
|------|----------|----------|------|------|
| **正常履约** | `user_001` ~ `user_080` | `order_001` ~ `order_080` | 80 | 各阶段正常/常规售后，无预埋诊断捷径 |
| **异常待咨询** | `user_081` ~ `user_120` | `order_081` ~ `order_120` | 40 | 仅写入客观事实，Case 由引擎 + 用户话术推理 |

**原则**：数据库里**没有** `diagnosis_case`、`merchant_reject` 等答案标签；异常靠事实组合 + 用户怎么说。

## 二、正常样本（user_001 ~ 080）

| 编号范围 | 履约阶段 | 订单状态概览 | 演示话术 |
|----------|----------|--------------|----------|
| **001 ~ 020** | 刚下单 | `unused`，未核销 | 「查看券码」「这单还能用吗」 |
| **021 ~ 038** | 已预约 | `scheduled`，有预约时间 | 「服务进度到哪了」「预约几点」 |
| **039 ~ 054** | 刚核销 | `used`，近期核销 | 看 **+ → 服务进度 / 操作记录** |
| **055 ~ 062** | 较早完成 | `used`，较早消费 | 历史履约查询 |
| **063 ~ 071** | 过期未用 | `expired` | 「过期了怎么办」 |
| **072 ~ 076** | 退款中 | `refunding` | **+ → 操作记录**（退款处理中） |
| **077 ~ 080** | 已退款 | `refunded` | **+ → 操作记录**（退款已原路返回） |

适合向老板展示：**查单、查券、履约时间线、操作记录、退款进度** 等「管家」基础能力。

## 四、5 分钟老板演示脚本

1. **user_022** → 「服务进度到哪了」→ **+ 服务进度**（正常预约链路）
2. **user_075** → **+ 操作记录**（退款进行中）
3. **user_090** → 「店关门了券还能用吗」（POI 事实 → 诊断）
4. **user_104** → 「在这家店扫不了」（跨店事实 → PC-008）
5. **user_081** → 「老板说不认券」（话术 + 有效券 → FC-006）

## 五、时间与规则说明

- **周末/午市/营业时段**：按服务器 **Asia/Shanghai 当前时刻** 判断。
- **订单/券上的时间**：API 每次启动会 `mock_time_shift` 对齐到「现在」附近。
- **状态栏时钟**：前端显示本机实时时间。

若数据看起来「过期」或时间不对，本地执行：

```powershell
docker compose restart api
```

或全量重置：

```powershell
docker compose down -v
docker compose up --build -d
```
