# 产品定义

## 项目名称

抖音生活服务 AI 履约服务管家（Demo）

---

## 一、产品定位

**AI 履约服务管家** —— 嵌入用户履约旅程，帮用户把一次生活服务消费做完、做好。

不是 FAQ、不是独立聊天机器人、不是传统智能客服。

**成功标准**：用户问题是否被解决。

---

## 二、核心价值

| 对象 | 价值 |
|------|------|
| **用户** | 降低查单/理解/处理成本；提升履约成功率与体验 |
| **商家** | 减少重复咨询与履约失败；提升到店率与核销率 |
| **平台** | 提升 GMV、核销率、用户与商家留存 |

---

## 三、Demo 边界（P0）

聚焦验证：**AI 能否成为生活服务场景的第一服务入口**。

已实现：

- **Plan → Gather ReAct → Compose** 统一 Pipeline + SDS 诊断
- 120 用户 mock 场 + 流式思考（真实推理）与流式回复
- 履约时间线、操作记录、退款可视化

---

## 四、用户旅程

```text
发现团购 → 购买订单 → 预约 → 到店 → 核销 → 售后
```

AI 嵌入各节点：购后卡片、到期提醒、到店核销、失败诊断、售后办理。

---

## 五、Agent 能力闭环

```text
Understand → Observe → Diagnose → Execute → Explain
```

Agent 必须能：**查询、解释、办理、转人工**。

每次回复尽量附带可执行能力：查订单、查券码、重新生成核销码、联系商家、创建预约、申请退款、转人工。

---

## 六、Tool Calling 原则

业务能力通过 Tool 实现；结论来自工具结果 + 诊断树，而非 Prompt 硬编码。

核心工具包括：`query_order`、`query_voucher`、`query_store`、`search_knowledge`、`run_diagnosis`、`create_reservation`、`apply_refund`、`human_handoff` 等。

工具调用与结果对用户可见（思考流 + 操作记录）。

---

## 七、UI 原则

参考「会话即服务」：

- **主界面**：全屏会话 + 焦点订单 + 流式思考 + 服务卡片
- **+ 半屏**：服务进度、历史订单、操作记录、授权设置
- **Demo 用户切换**：120 用户覆盖正常与异常场景
- **状态栏**：实时时钟

聊天是载体；进度、记录、办理与对话同等重要。

---

## 八、体验场景矩阵

| 场景 | 体验方式 |
|------|----------|
| 查单/查券 | 正常用户 + 「查看券码」「订单到哪了」 |
| 预约 | user_096 等 + 「没预约能核销吗」 |
| 核销失败 | 异常用户 + 「扫不出来」「老板说不认券」 |
| 门店问题 | 「店关门了」「搬迁了去哪」 |
| 售后退款 | 「我要退款」+ 操作记录 |
| 安全投诉 | 「吃坏肚子」→ P0 升级 |
